# M3.5 — Privremeni mini UI

Ovaj milestone nije bio u prvobitnom planu. Dodat je da bi se rad simulatora video pre nego
što stigne pravi UI u M6. Deo ovog koda se svesno baca.

## Cilj

Prvi put videti izvršavanje programa u browseru: textarea, dugme Step, prikaz registara i
marker `>` na tekućoj liniji. Bez memorije, breakpointa i stilizovanja po mokapu.

## Šta je urađeno

- `index.html` — tri kolone: kod, izvršavanje, registri
- `src/ui/main.ts` — povezivanje dugmadi sa `assemble()` i klasom `Cpu`
- `src/style.css` — minimalni stilovi, samo da bude čitljivo

Tok: izmena teksta → asembliranje → ako ima grešaka ispiši ih, inače napravi `Cpu` →
`Step` poziva `cpu.step()` → ponovo se iscrtavaju registri i marker.

## Ključne odluke

| Odluka | Alternativa koju smo odbacili | Zašto |
|---|---|---|
| Kod se asemblira na svaku izmenu teksta, ne tek na Step | Asembliranje samo pri pokretanju | Greške se vide dok kucaš, i marker `>` stoji na prvoj instrukciji pre prvog koraka |
| Svaka izmena koda poništava procesor | Nastaviti izvršavanje nad starim programom | Inače bi marker pokazivao na liniju koja više ne postoji |
| Ceo prikaz se iscrtava iznova posle svakog koraka | Ažurirati samo promenjene registre | Na 32 registra razlika u brzini je nemerljiva, a kod je znatno prostiji |
| Registri se prikazuju u `<pre>` kao poravnat tekst | HTML tabela | Privremeno rešenje; monospace poravnanje je dovoljno i najbrže za napisati |

## Zamke i problemi

- **`querySelector` vraća `null` ako element ne postoji**, pa TypeScript u strict režimu ne
  dozvoljava da se rezultat odmah koristi. Umesto potiskivanja provere uveden je pomoćnik
  `element()` koji baci jasnu grešku ako u HTML-u nema traženog elementa — greška u imenu
  selektora se tako vidi odmah, a ne kao nerazumljivo „null".
- **Heksadecimalni prikaz negativnih brojeva** zahteva `value >>> 0`: bez toga bi `-1` bio
  ispisan kao `-1`, a ne kao `FFFFFFFF`. `>>> 0` tumači isti niz bitova kao broj bez znaka.

## Kako je testirano

Ručno, u browseru (ovaj sloj nema automatske testove — logika koja se testira je u `core/`):

- program `LI x1, 5` / `LI x2, 7` / `ADD x3, x1, x2` / `MV x4, x3` korak po korak;
  posle prvog koraka `x1 = 00000005`, marker prelazi na sledeću liniju;
- pogrešan kod (`MULT`, nedefinisana labela) — obe greške se ispisuju sa tačnim brojem
  linije dok se kuca, i Step je onemogućen dok se ne isprave;
- po završetku programa status prelazi u „program zavrsen".
